# Agents evolution

This file records the product boundary across released generations. It is
historical context, not an active instruction source or deployment asset.

| Generation | Retained purpose | Retired active machinery |
|---|---|---|
| 1.x | Project isolation, durable rules, memory templates and controlled handoff | Roster/controller language and fixed coordination templates |
| 2.x | Ledger-backed dispatch, deployment ownership, readiness checks and runtime evidence | Enterprise dispatch assumptions, multi-agent requirements and score-oriented gates |
| 3.x | Native Codex skills, source-checked knowledge, Provider/Consumer validation and safe deployment | Mandatory routing hierarchy, chat envelopes, model probes, comparison runners and synthetic scores |
| 4.x | Immutable knowledge, revisioned tasks, registered runtime artifacts, retention and release evidence | Fixed host settings and undocumented local model claims |
| 5.x | Cross-platform PowerShell CLI, explicit v4 migration, plugin distribution and planned validation | v3/v4 readers and legacy rules in the active deployment surface |

The invariant is a project governance workflow: authorized rules, verifiable
knowledge, recoverable task state and owned deployment changes. Generation
changes do not grant memory permission, replace the user's current goal or
promise model accuracy.

v4 records and evidence are retained only as migration provenance under the
history boundary. v5 consumers use the explicit migration command and receive a
new manifest, schema set and runtime contract.
